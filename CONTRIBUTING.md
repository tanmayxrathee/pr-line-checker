# Contributing to DriftCheck

Thank you for your interest in contributing to DriftCheck! This document outlines the rules and conventions you must follow.

## Hackathon Compliance Rules (Non-negotiable)

These rules are **non-negotiable** and enforced by CI. A feature isn't done if it breaks one.

1. **`HACKATHON.md` is the first commit and must never be modified.** CI enforces it via `scripts/check_hackathon_md.py`.

2. **Every change goes on a new branch and through a PR.** No direct pushes to `main`. Branch protection requires PR + CI `test` job to pass.

3. **CI runs tests on every PR. Merge only when CI is green.** Solo contributors may merge their own PR after CI passes.

4. **Every commit message and every PR names the coding agent and the project's models.**

   ```
   P1.2.1: Add argparse flag extractor

   Coding agent: OpenCode (Nemotron-3-Ultra-550B via NVIDIA NIM)
   Models used in project: Qwen3-4B (local), Nemotron-3-Ultra-550B (NVIDIA NIM)
   ```

   If a feature is built with a different agent (Claude Code, Cursor, Copilot...), change **only** the `Coding agent:` line. The `Models used in project:` line never changes.

5. **`.github/pull_request_template.md`** exists and asks for the models. Use the official template text from the Problem Statements document.

6. **Real tests for real code.** No `assert True`.

7. **CI workflow installs the project and runs the tests, and must pass on the last commit.**

8. **`examples/`** contains real inputs and the **real output the tool produced** (generated by a script, never hand-written).

## Branch Naming

Every feature must use its own branch named:
```
feat/<ID>-<short-slug>
```

Examples:
- `feat/P1.2.1-argparse-flag-extractor`
- `feat/P2.2.1-sentence-splitter`
- `feat/P3.2.1-tier1-rules`

The `<ID>` comes from the PLAN.md feature card (e.g., `P1.2.1`).

## Commit Message Format

Every commit message must end with:

```
<ID>: <title>

Coding agent: <your agent name and model>
Models used in project: Qwen3-4B (local), Nemotron-3-Ultra-550B (NVIDIA NIM)
```

Example:
```
P1.2.1: Add argparse flag extractor

Coding agent: OpenCode (Nemotron-3-Ultra-550B via NVIDIA NIM)
Models used in project: Qwen3-4B (local), Nemotron-3-Ultra-550B (NVIDIA NIM)
```

## Pull Request Title Format

PR title must match the commit format:
```
<ID>: <title>
```

Example:
```
P1.2.1: Add argparse flag extractor
```

## Development Workflow

1. **Read PLAN.md §0–§4** and the feature card for your assigned feature.

2. **Create a feature branch** from `main` (or `staging` if that's the development branch):
   ```bash
   git checkout main
   git pull
   git checkout -b feat/P1.2.1-argparse-flag-extractor
   ```

3. **Implement the feature** modifying only the files listed in the feature card.

4. **Write tests** as specified in the feature card. Run them locally.

5. **Run `make check`** (ruff + mypy + pytest) before pushing.

6. **Push and create a PR** against `main` (or `staging`).

7. **Wait for CI to pass** (green checkmark).

8. **Merge the PR** (solo contributors may self-merge after green CI).

## Models Used in This Project

- **Qwen3-4B (local)** - Tier 2 judge, served via llama.cpp
- **Nemotron-3-Ultra-550B (NVIDIA NIM)** - Verifier, served via NVIDIA NIM API

Do not introduce additional models or agents without explicit authorization.

## Coding Agent

This project uses **OpenCode** with **Nemotron-3-Ultra-550B via NVIDIA NIM** as the primary coding agent.

If you use a different agent for a specific task, update only the `Coding agent:` line in commit messages and PRs. The `Models used in project:` line must remain unchanged.
